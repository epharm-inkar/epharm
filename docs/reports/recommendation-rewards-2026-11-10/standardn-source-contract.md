# Стандарт-Н: единицы упаковок и возвраты — локальная проверка источника

Этот протокол относится к DR1–DR3 в разделе
[«Локальные упаковки, возвраты и Windows-пилот» актуального PLAN.md](../../../PLAN.md).
Исследована настоящая демо-база и штатный интерфейс Стандарт-Н на изолированной
Windows-VM без сетевых адаптеров. Production и реальные профили не изменялись.
Это проверка контракта источника; полный денежный Windows-пилот DR4 ещё проверяет
интеграционный владелец. Мобильные тесты не запускались.

## Что подтверждено нативным интерфейсом и read-only SQL

| Факт                            | Контрольная продажа            | Возврат именно этой продажи             |
| ------------------------------- | ------------------------------ | --------------------------------------- |
| `DOCS.ID`                       | `23651`                        | `23652`                                 |
| `DOC_TYPE`, `STATUS`            | `3`, `1` — проведённый чек ККМ | `9`, `1` — проведённый чек возврата ККМ |
| Ссылка на оригинал              | `PARENT_ID=0`                  | `PARENT_ID=23651`                       |
| ID строки до → после проведения | `61043 → 42375`                | `61044 → 42377`                         |
| `QUANT`, `HUMAN_QUANT`          | `-1`, `"1"`                    | `+1`, `"1"`                             |
| `PRICE`, `SUMMA` строки         | `3195`, `-3195`                | `3195`, `+3195`                         |
| `DOCS.SUMMA`                    | `-3195`                        | `+3195`                                 |
| `VNUM`, `VSHIFT`                | `1`, `1`                       | `2`, `1`                                |
| `COMMITDATE`, нативное время    | `2026-11-10 03:34:41.727`      | `2026-11-10 03:44:01.953`               |
| `POSTDT`, нативное время        | `2026-11-10 03:34:42.475`      | `2026-11-10 03:44:02.662`               |

Касса работала в режиме демо без подключённого фискального регистратора. Счётчики
выставлены самой демо-программой; это не внешнее подтверждение ККМ/OFD.
`DOC_DETAIL.PARENT_ID=0` у проверенной строки возврата: связью с исходной продажей
служит подтверждённый **родитель заголовка**, а не придуманная ссылка строки.
Проверенная пара не использовалась для исторического начисления или backfill.

## Единица количества

- Контролируемый ввод одной целой упаковки записал `HUMAN_QUANT="1"` и
  `abs(QUANT)=1`. При проведении `HUMAN_QUANT` переносится без преобразования.
- В сохранённой истории демо обнаружены пары `3/10 ↔ abs(QUANT)=0.3` и
  `10/30 ↔ abs(QUANT)≈0.333333…`. Это подтверждает дробный **формат источника**.
- Текущие попытки дробного отпуска через интерфейс, включая товар с остатком
  `75/100`, отклонены сообщением «Товар неделимый». Успешная контролируемая
  дробная продажа **не заявляется**; делимость товара ради теста не менялась.
- `KOEF` — служебный флаг участия строки в складском учёте, не коэффициент
  пересчёта в упаковки. `PACKET` относится к репликации, не к числу упаковок.
  Пустое `EDIZM` само по себе также не доказывает единицу.

[Классификатор единиц](../../../App/Services/StandardNQuantityUnits.cs) выдаёт
`full_package` только для явного целого ASCII-значения `HUMAN_QUANT`, точно
совпадающего с модулем исходного количества. Дробь, отсутствие поля, несовпадение
или неизвестный формат остаются `unknown` и не разрешают автоматический бонус.
Нативные количества и суммы не округляются и не подменяются. Существующий wire
с целочисленными суммами KZT не расширялся: неподдерживаемая дробная денежная
сумма сохраняет исходные наблюдения без ложного отчёта об оплате.

## Связь ACTIVE и проведённых строк

`PR_DOC_DETAIL_INSERT` создаёт новый `DOC_DETAIL.ID`; равенство с ACTIVE ID
не является штатным контрактом. Общей финансовой таблицы соответствия не найдено.
Врачебные и рецептурные связи для этой задачи не читаются.

[Нативный linker](../../../App/Services/StandardNFinalLineLinker.cs) сопоставляет
только уникальную пару внутри одного физического документа по сохранённым
`PART_ID`, количеству, цене, сумме, скидке и `HUMAN_QUANT`. Реальный posted ID
остаётся `sourceLineId`; исходный ACTIVE ID передаётся отдельно как
`observedSourceLineId` с `lineLinkSource=standardn-unique-final-line`.
Повтор после сбоя очереди сохраняет уже проверенную исходную связь. Дубликаты
кандидатов или изменившиеся поля не создают связь и требуют HQ.

`HUMAN_QUANT` в проведённых строках выбирается только после проверки метаданных
поля. Если старый вариант схемы не содержит поддерживаемого столбца, обычное
чтение продаж сохраняется, а единица остаётся неизвестной. Новые wire-поля
необязательны для старых клиентов.

## Захват возвратов и повторная доставка

[Отдельный наблюдатель](../../../App/Services/NativeRefundCapture.cs) использует
read-only чтение проведённых документов типа `9` и источники
`standardn-db-refund` / `standardn-posted-refund`. Он не выдаёт общий сигнал
печати за доказательство возврата и не переименовывает старую отложенную продажу.

Cursor v2 фиксирует время активации по часам БД и первоначальный максимум ID.
Ограниченные проходы повторяются с начала: порядок генератора ID не считается
порядком commit. Поэтому невидимая транзакция с меньшим ID будет найдена после
позднего commit, даже если более высокий ID уже обработан. Старые проведённые
возвраты до активации не импортируются. Документ, выделенный до активации,
но проведённый после неё, обнаруживается по `POSTDT`.

Стабильный `saleId` и enqueue перед сохранением состояния делают повтор после
сбоя идемпотентным. На диске сохраняются до **256 ожидающих** и **16 384
поставленных в outbox** ID; размер одного состояния ограничен 1 МиБ. При достижении предела
обработчик останавливается перед потерей незапомненного документа и пишет
диагностику; работа кассира продолжается. Повреждённый или прежний локальный
cursor v1 не сбрасывается в ноль и не перезаписывается. При изменении источника
создаётся отдельная исходная граница без импорта старой истории.

Проверка печати исключает известный возврат и неоднозначные случаи из
подтверждения обычной продажи. Старый активный черновик возврата не подавляет
недавно проведённый подтверждённый чек типа `3`; посторонние отложенные документы
не получают его сигнал печати. Функциональность опциональна и по умолчанию
выключена.

Сервер сохраняет возврат и спор HQ, не списывая уже начисленный бонус.
Первоначальный фискальный регистр передаётся только из подтверждённого
оригинального документа, а не подменяется текущим регистром возврата. Возвраты
не увеличивают продажную атрибуцию, GMV и отчётные продажи; сырые записи журнала
сохраняются. Неизвестная или противоречивая исходная ссылка требует HQ.

## Проверки и остающаяся граница

- Целевые native-проверки: **113/113 PASS**.
- Полный portable POSM: **723 PASS / 15 Windows-only SKIP / 0 FAIL**.
- Cross-build настоящего WPF App и UI harness: **0 ошибок, 0 предупреждений**.
- Регрессии включают поздний невидимый commit, pending holes, перезапуск,
  отсутствие backfill, границы состояния, сбой очереди, сохранение ACTIVE alias
  при повторе и защиту обычной печати от возвратного сигнала.

Cross-build и portable-тесты не заменяют выполнение на Windows. Полный путь
реальный скан → фактический показ → новая добавка за 0–120 секунд → поздняя
оплата → однократный бонус → возврат/HQ без списания ещё требует итогового
протокола DR4. Этот документ не объявляет production готовым к включению и не
служит разрешением на деплой.
