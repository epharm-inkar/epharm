## Границы среды

Используется отдельная Windows DEMO без сетевых адаптеров, настоящий кандидат
backend и отдельный PostgreSQL на Mac. Синтетический сотрудник и отдельная акция
не относятся к production. Мобильное приложение не проверяется. Loopback/QGA
мост возвращает настоящий HTTP-ответ backend, не подставляет успешные результаты
и не является средством измерения пропускной способности.

В первом опыте не выдавалось положительное доказательство корзины: в DEMO были
три открытые сессии одного компьютера. Исправление не выбирает произвольную
сессию: возраст heartbeat должен быть от 0 до менее 300 секунд, две живые
локальные сессии остаются неоднозначностью. На повторе транспорт тестового моста
получал ошибки sharing violation, затем Windows сообщила о нехватке системных
ресурсов при записи штатного лога. VM остановлена штатно и перезапущена; база
сохранена. Причина исчерпания ресурсов не объявляется доказанной.

В UTM 4.7.5 принудительная отмена chunked CLI file transfer способна оставить
гостевой handle открытым. Для повторного стенда QGA transfer сериализован,
увеличен только технический deadline CLI (30 секунд), опрос сокращён до 2/с;
первый timeout прекращает дальнейший QGA I/O. Денежные ограничения свежести
источника и печати, 120 секунд на добавление товара и серверная проверка оплаты
не ослаблялись.

При отмене неоплаченного последнего DEMO-чека уменьшается MAX(DOCS.ID). Это
не является самостоятельным доказательством восстановления БД. Исправление
`7a9682b8` сохраняет высокий watermark и продолжает ограниченный обход возвратов;
фиксированный cutoff, идентичность источника, pending/completed и защита от
повторов сохранены. Четыре регрессии сначала воспроизвели ошибку, затем прошли.
Точная DLL после установки в VM проверена SHA256.

[Протокол Windows-only проверок](windows-core-results.json): runner завершил
29 проверок за 130,576 секунды; доказательство — законченные XML и stdout.
Пустой exit-файл QGA сам по себе не используется как доказательство успеха.

## Проверенная нагрузка точного backend-кандидата

[Фильтрованный протокол](load-1500-results.json): 1500 аутентифицированных
сотрудников / 500 синтетических аптек, peak 48 одновременно выполняемых HTTP
запросов при лимите 50. Прогон длился 185 секунд с настоящей задержкой оплаты
125 секунд и 1500 совпадающими контекстами РПС. Отдельный guarded SQL-оракул
подтвердил 1440 начислений по 400 ₸ (две упаковки × 200), всего 576000 ₸,
60 отрицательных сценариев без денег, отсутствие дублей и перерасхода бюджета.
Ошибок HTTP, нарушений порогов и deadlock не обнаружено; штатные sale p95
18,53 мс, recommend p95 11,23 мс. Все UTM VM были остановлены; ресурсы
стенда ограничены, контейнеры после проверки остановлены, данные сохранены.
Это локальная синтетическая проверка, не доказательство мощности production
или завершённого нативного Windows-пути.

Повтор Windows подтвердил видимый показ, полный baseline, добавление целой
упаковки через 22,10 секунды и проведённый чек 23660 через более двух минут.
Автоматическое начисление этого опыта **не прошло**: paid-документ отсутствует
в server sales, баланс 0. Обнаружен прежний предфильтр native print guard,
который отбрасывает POSTDT старше пяти секунд после человеческого диалога печати.
Raw vendor log содержит завершённый print batch и точный Destroy ID внутри него;
исправление `a755c074` привязывает именно эти IDs с сохранением проверки оплаты.
До нового положительного прогона строка Windows-приёмки остаётся PENDING.
